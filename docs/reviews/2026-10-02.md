# Policy and input handling review — 2026-10-02

Base: `f9a6cc308b48ce3ce5280368c5308f3b1d036053` (after 0.5.0).
Runtime dependency: `@anthropic-ai/sandbox-runtime` **0.0.78**, unchanged.

This review follows a request from observation or a refusal through policy editing,
credential resolution, execution settings, audit storage and the CLI, console and MCP
surfaces. It also inspects environment construction, protected paths, worktree handling,
process cleanup and packaging. The changes below address reproduced Seisin defects;
this is not a claim that every possible boundary bypass has been ruled out.

## Findings corrected

| Area | Before | After and regression evidence |
| --- | --- | --- |
| Observation proposals | Reconstructed lists dropped isolation, subtractions, providers, per-role network/MCP choices and other settings. | Starts from current policy text; settings, comments and idle roles survive. |
| Observed identities and paths | Removed roles could reappear, a host path could become relative territory, and alternate key directories lost their identity. | Only current roles receive additions, outside writes are filtered before generalisation, and keys retain their directory. |
| Policy decisions | A CLI/console approval could check an older config than the text edited under the lock. | Loads and checks the text held under that lock. A newly added `never_writes` refuses the pending grant. |
| Policy validity | A grant could write invalid text and settle the request. | Validates before writing or settling; an absolute write grant leaves both records untouched. |
| Text and file integrity | Indented lists/commented headers failed; atomic replacement reset file permissions and mixed line endings. | Grants preserve CRLF, recognise the supported table syntax, and retain the policy's mode, including `0600`. |
| Lock deadline | A directory or unreadable file at the lock name could cause indefinite retries. | Only a disappeared lock bypasses the ordinary wait; an obstructed lock reaches `ELOCKED`. |
| Stream redaction | The exported API relied on callers sorting values and removing empty strings. | Normalises its input and masks credentials split across chunks with an unsorted list. |
| JSON references | Nested fragments could resolve inherited JavaScript properties absent from the JSON file. | Every component must be an own property. |
| Dotenv errors | The trailing text of a malformed value appeared in an exception. | Explains the syntax error without echoing that text. |
| Role shape | Reference resolution required the parser's private `keyEntries` field. | Uses the same fallback from `keys` as public settings helpers. |
| Protected scan directories | Absolute directories were concatenated with the repo root; aliases of an ancestor also differed from the canonical root. | Absolute, relative and symlink-ancestor spellings produce the same exclusions. |
| MCP and audit framing | A burst of valid messages was treated as one oversized input; caps counted characters and could reinterpret a rejected line's suffix. | Caps each frame in UTF-8 bytes and discards the whole rejected frame through its newline. Later valid messages still work. |

The refusal for unsupported key injection now points to the implemented `env` and
`scratch` modes. There is no new delivery mode or change to the sandbox runtime pin.

## Dependency finding still open

`npm audit --json` on 2026-10-02 reports two high-severity package entries for one
transitive advisory: `node-forge` and the runtime that depends on it.
[GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv), updated
2026-10-01, lists versions through 1.4.0 as affected and no patched version. The npm
registry's latest `node-forge` at this check is 1.4.0. No claim about exploitability
through Seisin is made by this dependency check.

The automatic npm suggestion is to downgrade the sandbox runtime to 0.0.50. That is
an unvalidated change to the enforcement dependency, so it was not applied. This
finding remains open for a patched dependency and runtime compatibility validation.

## Validation and limits

- All **17** tests in `test/audit-hardening.test.js` fail against the original base and
  pass after these changes. The lock regression runs in a subprocess with a deadline,
  so the original indefinite wait cannot hang the test runner.
- The focused suite covering these regressions, MCP, protected surfaces, console controls
  and project vocabulary passes **65/65**, without skips, on Node **24.19.0**.
- Broader portable validation selects the existing suite while explicitly excluding
  runtime/platform tests and the two Unix-socket tests unsupported by this host. Its exact
  outcome is **766 selected tests passing, zero failures** on Node 24.19.0; the remaining
  62 of the 828 tests are not executed by this selection. Exclusions are a local test invocation; no skip
  conditions or CI enforcement checks have been relaxed in the repository.
- The unchanged kernel tests still require a host that allows the real runtime to enforce
  the boundary. This managed host denies nested user namespaces and Unix-socket binding;
  the initial full-suite attempt encounters those environmental failures. The portable
  run is not evidence that those boundary tests pass. The existing macOS/Linux CI matrix
  must supply that evidence before merge.
- Syntax, diff whitespace and npm package contents are checked locally. The new shared
  framing module ships through the existing `src` packaging rule.

The dated macOS/Linux measurements elsewhere in the documentation remain historical.
This first pass brought the suite to **828 tests**; the
[follow-up](2026-10-02-followup.md) adds 15 more, bringing it to **843**. This review
does not relabel the 2026-09-30 result as a current full-suite pass. No release or
version bump is part of this change.
